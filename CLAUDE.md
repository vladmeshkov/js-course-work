# Курсовая работа по веб-разработке: ДБО физических лиц

Контекст проекта для новых сессий. Источник: обсуждение с пользователем и бланк задания «БЛАНК ВЕБ.docx» (сам файл в репозитории отсутствует; ниже его пересказ).

## Цель
Курсовая проект на Node.js: система дистанционного банковского обслуживания (ДБО) физлиц. Должна быть качественным продуктом для резюме (практика в банке). Язык общения с пользователем: русский.

## Технические решения для «плюса к резюме»
- Двойная запись (double-entry ledger): остаток считается по проводкам.
- Деньги в копейках (целое) или DECIMAL, не float. Переводы в транзакции MySQL с блокировкой строк и идемпотентностью.
- Курсы валют из api.nbrb.by; каталог платежей по образцу ЕРИП.
- Безопасность: bcrypt/argon2 (не SHA-256), TOTP 2FA, HTTPS, CSRF, лимит попыток входа, журнал аудита, pg_dump по расписанию.
- Схема БД в чистом SQL (нужен скрипт для приложения), без ORM-генерации.
- Автотесты (Jest + supertest), README со скриншотами, запуск одной командой.
- Собственный CSS без Bootstrap/Tailwind (требование одной таблицы стилей). Цвета через CSS-переменные, тёмная тема переключается классом на body.

## Архитектура кода (принято, каркас готов)
Подробная концепция модулей, ролей, EOD и IDEF0: `docs/concept.md` (приложена пользователем из чата по записке). Записку пользователь пишет в другом чате, здесь только код.

- Фронтенд: без шаблонизаторов и фреймворков. Express отдаёт JSON API (`/api/...`) и статику, интерфейс собирает клиентский JavaScript: `public/index.html` (оболочка), `public/js/lib` (маршрутизатор на History API, `html` с экранированием, запросы к API, формы, анимации), `public/js/routes` и `public/js/pages` (маршруты и страницы по модулям). Соглашения: `docs/frontend.md`. Одна таблица `public/css/style.css`, палитра orange через класс `pal-orange` на body.
- Слои: routes -> controllers (тонкие, отдают JSON) -> services (вся бизнес-логика) -> models (SQL). Контроллеры не пишут SQL, модели не знают про HTTP. Маршруты API лежат в `src/routes/<модуль>.js`.
- ES modules, JSDoc вместо типов. Конфиг из `.env` через `src/config`.
- Деньги: целые копейки (BIGINT), форматирование только в `lib/money.js`. `balance` счёта = Кт минус Дт.
- Любая денежная операция идёт через `ledgerService.post` (двойная запись, блокировка счетов по возрастанию id, идемпотентность, холды, сторно). Проводки и аудит неизменяемы (триггеры в БД).
- Каждая операция в одной транзакции (`withTransaction`), клиент транзакции передаётся в сервисы и модели параметром `db`.
- Права: у роли набор прав (`permissions`), маршруты проверяют право (`requirePermission`) или `requireStaff`, не название роли.
- База: MySQL 8 (InnoDB, `mysql2`). Слой доступа `src/db/pool.js`: `query(sql, params)` с плейсхолдерами `?` возвращает `{ rows, rowCount, insertId }`, `withTransaction` (READ COMMITTED, UTC), DATE как строка, TINYINT(1) как boolean, DECIMAL как число. Вместо RETURNING берётся `insertId`, вместо `ON CONFLICT` `ON DUPLICATE KEY UPDATE`, JSON-столбцы пишутся через `JSON.stringify`, зарезервированные слова в SQL берутся в обратные кавычки (`key`, `system`). Сессии хранит собственный `MysqlStore` в таблице `sessions`.
- Схема БД: `db/sql/NNN_*.sql`, применяется `npm run db:migrate`, `npm run db:schema` собирает `db/schema.sql` для приложения (его выполняет и клиент mysql, и Workbench). Новый модуль = новый SQL-файл + model + service + controller + route (API) + страница в `public/js/pages` + тесты.
- Безопасность: bcrypt, сессии в MySQL, CSRF-токен в сессии (клиент берёт его из `GET /api/session` и шлёт в заголовке `X-CSRF-Token`), helmet (CSP), лимит входов, блокировка после N неудач, паспорт и идентификационный номер шифруются AES-256-GCM.
- Тесты: Vitest + supertest (`test/http.js`: клиент API с cookie и CSRF), отдельная база `talerbank_test` (пересоздаётся при запуске, нужен запущенный MySQL; параллельно можно гонять на своих базах через `TEST_DATABASE_URL=...talerbank_test_имя`). Резервные копии требуют `mysqldump` и `mysql` в PATH (или `MYSQL_BIN_DIR`).
- Роли в БД: client, operator, credit_officer, monitoring, admin (в макетах: Клиент, Сотрудник, Администратор; сотрудники = роли с разными правами).
- Готово (по docs/concept.md): каркас, схема БД (24 SQL-файла в `db/sql`, в том числе юань CNY), регистрация и проверка анкеты, счета (открытие и закрытие, IBAN), переводы (между своими с конвертацией, клиенту по IBAN, лимит, комиссия, код), курсы НБ со спредом, вклады, кредиты (скоринг, ДН 40 %, графики, просрочка и пеня, досрочное погашение), закрытие операционного дня (`/admin/eod`), карты (лимиты, блокировка, покупка), каталог платежей (шаблоны, автоплатежи, квитанции), антифрод (очередь, холды, особый контроль), выписка, справка и квитанции в PDF, администрирование (курсы и тарифы, пользователи, журнал аудита, резервные копии с шифрованием, отчёты и ОСВ), рабочее место операциониста (анкеты, касса, блокировка счетов), двухфакторная защита TOTP (`twoFactorService`, `lib/totp.js` по RFC 6238, QR, резервные коды, страница `/security`), внутренние уведомления (`notificationService`, колокольчик в шапке, `/notifications`, напоминание о платеже за 3 дня при закрытии дня), 274 теста, обязательная 2FA для сотрудников (настройка `security.require_2fa_staff`, middleware `enforceStaff2fa`), межбанковские переводы через клиринг (`interbankService`: код, антифрод по тем же правилам (`fraudService.evaluateInterbank`, задержка в статус `review`, решение специалиста), холд, пакет при закрытии дня, отклонение неактивным банком, входящие платежи у операциониста, `/admin/clearing`), главная сотрудника по ролям (`staffDashboardService`: показатели и ближайшие задачи только по правам роли), главная клиента по макету (`dashboardService`: сумма по счетам в BYN, четыре плитки продуктов, операции, курсы), тёмная тема (класс `dark` на `<html>`, переменные в `public/css/style.css`, переключатель в верхней полосе, выбор хранится в localStorage, по умолчанию тема системы; скрипт `public/js/theme.js` подключён в `<head>`, чтобы не было мигания).
