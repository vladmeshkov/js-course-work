# Диаграммы (draw.io)

Файлы открываются в draw.io (https://app.diagrams.net или приложение diagrams.net): «Файл → Открыть с устройства». Внутри файла несколько страниц, они переключаются вкладками внизу окна. Экспорт в картинку: «Файл → Экспортировать как → PNG/SVG/PDF».

| Файл | Диаграмма | Откуда берётся |
|---|---|---|
| `er.drawio` | ER-диаграмма базы данных: **страница 1 «Основные сущности (для записки)»**: 19 главных таблиц с ключами и несколькими полями, это то, что идёт в раздел 4.1.4. Дальше по странице на каждый модуль (счета и проводки, переводы, вклады, кредиты, карты, платежи, антифрод, ...) | автоматически из работающей базы MySQL |
| `classes.drawio` | диаграммы классов: слои приложения (контроллеры, сервисы, модели), сервисы бизнес-логики и их зависимости, модели доступа к данным, библиотеки | автоматически из исходного кода `src/` |
| `usecases.drawio` | диаграмма вариантов использования: гость, клиент и четыре роли сотрудников | описана в `scripts/uml-drawio.js` |
| `sequence.drawio` | диаграммы последовательности: перевод клиенту банка, заявка на кредит, закрытие операционного дня | описаны в `scripts/uml-drawio.js` |
| `class-diagrams.drawio` | две диаграммы классов по образцу учебных (три отсека, кратности, агрегация и композиция): ядро предметной области (10 классов) и слой бизнес-логики (9 сервисов) | `npm run uml:classes` (`scripts/class-diagrams.js`) |
| `views.drawio` | модели представления для раздела 1.5, по одной диаграмме каждого вида: варианты использования, последовательность, деятельность, состояния (процесс кредита), компоненты, развёртывание | `npm run uml:views` (`scripts/uml-views.js`) |

## Как перестроить

Диаграммы ER и классов можно пересоздать после любого изменения базы или кода:

```
npm run er:drawio     # ER по базе из DATABASE_URL
npm run uml:drawio    # классы, варианты использования, последовательности
```

Файлы перезаписываются. Если вы вручную поправили расположение в draw.io, сохраните файл под другим именем, иначе правки пропадут.

## ER в MySQL Workbench (если нужен именно такой вид)

База проекта работает под MySQL, поэтому диаграмму можно получить прямо из неё. В Workbench: «Database → Reverse Engineer...», подключитесь к базе `talerbank` и выберите все таблицы. Либо «File → Import → Reverse Engineer MySQL Create Script...» и файл `db/schema.sql` (полный скрипт создания базы). Диаграмма из всех 38 таблиц получается громоздкой, для записки используйте страницу «Основные сущности» из `er.drawio`.

## Вид ER-диаграммы

Таблицы нарисованы в стиле MySQL Workbench: синий заголовок, значки столбцов (жёлтый ромб: первичный ключ, красный: внешний ключ, синий: обычное поле, пустой: поле может быть пустым), серая полоса Indexes, связи пунктиром с «вилкой» (ER-нотация «ворона лапка») и прямыми углами.

## Как устроена ER-диаграмма

Скрипт `scripts/er-drawio.js` читает схему так же, как это делают графические клиенты: запрашивает у MySQL системное представление `information_schema` (таблицы, столбцы и типы, первичные ключи, внешние ключи) и рисует из этого файл draw.io. Ключи помечены `PK` и `FK`, связи нарисованы по внешним ключам (на стороне «многие» стоит «вилка»). На странице модуля таблицы соседних модулей показаны серым.

## Что в диаграммах нужно доработать вручную

- Автоматическая раскладка не знает, какие связи важнее. Для плаката перетащите таблицы так, чтобы пересечений было меньше, и уберите лишние поля.
- Для нотации IDEF1X (если её требует руководитель) стили таблиц и связей придётся поменять в draw.io: набор фигур «Entity Relation» есть в левой панели.
- Диаграммы вариантов использования и последовательности описаны текстом в скрипте. Подписи можно править прямо в draw.io.
