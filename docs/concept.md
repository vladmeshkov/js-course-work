## 5. Концепция системы

### 5.1 Фундамент: учёт денег

- **Двойная запись (ledger).** Любая операция оформляется как *документ*, у которого есть набор *проводок* (Дт счёт / Кт счёт / сумма). Инвариант: Σ Дт = Σ Кт по каждому документу, иначе транзакция откатывается.
- Остаток счёта считается по проводкам. Хранимый остаток — это кэш, который обновляется в той же транзакции.
- Проводки **не удаляются и не правятся**. Ошибку исправляет **сторно** — обратная проводка.
- **Внутренние счета банка:** касса, корреспондентский счёт, доходы (комиссии, проценты по кредитам, спред), расходы (проценты по вкладам), ссудные счета, счета просрочки и пени.
- **Номер счёта IBAN BY:** `BY` + 2 контрольные цифры (mod 97, ISO 13616) + 4 символа кода банка + 20 символов номера счёта. В нашем ПС первые 4 символа номера счёта — код балансового счёта. Проверяем IBAN получателя при вводе.
- **Холды:** доступный остаток = остаток − холды − неснижаемый остаток.
- **Деньги** храним в копейках `BIGINT` или `NUMERIC(18,2)`, **никогда во float**. Правило округления одно на всю систему.
- **Идемпотентность:** у каждого перевода есть ключ, повторный запрос не создаёт второй платёж.
- **Против дедлоков:** счета блокируются всегда в порядке возрастания id.

### 5.2 Банковская дата и закрытие операционного дня (EOD)

Своя **банковская дата**, отдельная от реальной. Процедура «Закрыть операционный день» выполняет по порядку:

1. Проверку, что не осталось незавершённых документов.
2. Начисление процентов по вкладам.
3. Начисление процентов по кредитам.
4. Списание плановых платежей по кредитам; при нехватке средств — вынос на просрочку.
5. Начисление пени.
6. Обработку окончания сроков вкладов: возврат на счёт или автопролонгация.
7. Исполнение автоплатежей.
8. Проведение холдов (клиринг).
9. Проверку оборотно-сальдовой ведомости: Σ Дт = Σ Кт.
10. Перевод даты на +1 день.

Демо-режим «прокрутить N дней» нужен для защиты. Процедура EOD — кандидат на схему алгоритма (5.2).

### 5.3 Модули

- **Онбординг (KYC):** гость подаёт заявку (ФИО, идентификационный номер, паспорт, телефон). Статусы: подана → на проверке → верифицирована / отклонена. Операционист активирует клиента, система открывает первый счёт в BYN. Проверки: возраст 18+, дубли, формат идентификационного номера.
- **Счета:** открытие в BYN, USD, EUR, RUB. Закрытие — только при нулевом остатке и без привязок. Арест или блокировка: дебет запрещён, кредит разрешён. Взнос и выдача наличных через операциониста (Дт касса → Кт счёт клиента).
- **Карты (виртуальные):** номер по алгоритму Луна, CVV и PIN хранятся только как хэш. Статусы: выпущена → активна → заблокирована → перевыпущена / закрыта. Лимиты: на операцию, суточный, месячный, флаг интернет-платежей.
- **Переводы:** между своими счетами (с конвертацией), клиенту банка (по IBAN, карте, телефону), в другой банк (холд → проведение при EOD через корсчёт). Конвейер обработки:
  `валидация → лимиты → комиссия (тариф) → антифрод → OTP → блокировка строк → проводки → уведомление`.
- **Платежи (по образцу ЕРИП):** дерево каталога (категория → город → поставщик) с маской реквизита, шаблоны, автоплатежи, квитанция в PDF.
- **Валюты:** курс банка = курс НБ ± спред (спред задаёт администратор). Доход от спреда отражается отдельной проводкой.
- **Вклады:** каталог продуктов (срок, валюта, ставка фиксированная или «ставка рефинансирования + X», минимальная сумма, капитализация или выплата процентов, пополняемость, отзывный или безотзывный).
  - Ежедневное начисление: `проценты = остаток × ставка / 100 / 365` (в високосный год делим на 366).
  - Досрочное расторжение отзывного вклада: пересчёт по ставке «до востребования» и удержание переплаты сторно. Безотзывный вклад досрочно расторгнуть нельзя.
- **Кредиты (ключевой модуль):**
  1. Заявка: продукт, сумма, срок, доход, стаж, иждивенцы.
  2. Скоринг: каждому фактору даётся балл, итоговый балл сравнивается с порогом (cut-off).
  3. Долговая нагрузка: `DTI = (платежи по текущим кредитам + новый платёж) / доход`. По Инструкции НБ № 149 норма — **не более 40 %**.
  4. Решение: авто-одобрение / ручное рассмотрение кредитным специалистом / отказ с причиной.
  5. Договор: информация об условиях на 1 странице, подписание кодом OTP, открытие ссудного счёта.
  6. Выдача: Дт ссудный счёт → Кт текущий счёт.
  7. Обслуживание: ежедневное начисление процентов, списание в дату платежа при EOD. При нехватке средств — просрочка, пеня, корзины DPD (1–30, 31–60, 61–90, 90+).
  8. Досрочное погашение: частичное (клиент выбирает, уменьшить срок или платёж, график пересчитывается) или полное.
  - Аннуитетный платёж: `A = S · i / (1 − (1 + i)^(−n))`, где `i = годовая ставка / 12 / 100`.
  - Дифференцированный платёж: `платёж_k = S / n + остаток_k · i`.
  - На будущее: скоринговую карту можно заменить логистической регрессией (связка с курсом регрессионного анализа).
- **Антифрод:** движок правил с настраиваемыми параметрами (сумма выше порога; новый получатель + крупная сумма; N операций за M минут; первая операция после смены пароля; новое устройство или IP). Баллы риска дают решение: пропустить / запросить дополнительное подтверждение / отправить в очередь специалиста по мониторингу. Отдельно — пометка операций особого контроля по Закону № 165-З (порог задаётся в настройках).
- **Отчёты:** для клиента — выписка, справка об остатке, квитанции (PDF). Для банка — **оборотно-сальдовая ведомость**, кредитный портфель и доля просрочки, портфель вкладов, объём операций, доходы от комиссий и спреда.
- **Администрирование:** RBAC (роль = набор прав, маршруты проверяют право, а не название роли), журнал аудита только на дописывание, активные сессии, справочники (тарифы, лимиты, продукты, ставка рефинансирования, праздничные дни).

## 6. Функциональная модель IDEF0 (раздел 1.2, чертёж 5.1)

На кафедре требуют **один конкретный процесс с декомпозицией на 4 уровня** (контекстная диаграмма = 1-й уровень). По образцу прошлого курсача делаем 5 диаграмм: A-0, A0, A2, A4, A24. Правила: 3–6 блоков на диаграмме, имена блоков — глагол + существительное, стрелки согласованы между уровнями (туннелирование).

**Процесс:** «Предоставить потребительский кредит физическому лицу».
**Цель модели:** формализовать кредитование физлиц через ДБО от заявки до зачисления средств.
**Точка зрения:** кредитный специалист банка.

### Уровень 1 — A-0

- **Вход:** кредитная заявка (сумма, срок, продукт); анкетные данные (доход, стаж, занятость); сведения о счетах и обязательствах клиента в банке.
- **Управление:** Банковский кодекс РБ; Инструкция НБ № 149; Закон «О кредитных историях»; Закон «О защите персональных данных»; кредитная политика банка; условия кредитных продуктов; методика скоринга.
- **Выход:** кредитный договор и график платежей; средства, зачисленные на текущий счёт; мотивированный отказ; кредитное досье; сведения для Кредитного регистра.

## 9. Правила работы с кодом

- Код простой и понятный, структура проекта без лишних абстракций. Студент в основном пишет на Java, поэтому JS-код должен читаться легко.
- Никаких эмодзи и «AI-украшательств» в коде и выводе консоли, никаких баннеров вида `=====`.
- Идентификаторы в коде — на английском. Весь текст интерфейса и сообщения пользователю — на русском.
- Вся бизнес-логика в слое сервисов (Model), контроллеры тонкие. Каждая денежная операция выполняется в одной транзакции БД.
- Схема БД ведётся SQL-скриптом (он нужен в приложении к записке), со всеми внешними ключами и ограничениями `CHECK`.
- На бизнес-логику (проводки, проценты, график, скоринг, IBAN) пишутся юнит-тесты. Они же пойдут в раздел 3 записки.
