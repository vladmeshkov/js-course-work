# Руководство по установке и запуску

Инструкция для Windows 10 и новее. На Linux и macOS шаги те же, отличается только установка Node.js и PostgreSQL.

## 1. Что нужно установить

| Программа | Версия | Зачем | Где взять |
|---|---|---|---|
| Node.js | 20 или новее (LTS) | запуск сервера | https://nodejs.org |
| PostgreSQL | 16 | база данных | https://www.postgresql.org/download/windows/ |
| Git | любая | получение проекта (можно скачать архив) | https://git-scm.com |
| Браузер | Яндекс Браузер, Firefox, Chrome или Opera | работа с интерфейсом | |

При установке PostgreSQL запомните пароль пользователя `postgres` и порт (по умолчанию 5432). Вместе с PostgreSQL ставятся утилиты `pg_dump` и `pg_restore`, они нужны для резервных копий.

Проверьте установку, открыв PowerShell или командную строку:

```
node -v
npm -v
psql --version
```

Если `psql` не находится, добавьте в переменную среды `Path` папку `C:\Program Files\PostgreSQL\16\bin` или используйте приложение pgAdmin вместо `psql`.

## 2. Получение проекта

```
git clone https://github.com/vladmeshkov/js-course-work.git
cd js-course-work
```

Либо скачайте архив проекта с GitHub и распакуйте его. Путь к папке может содержать пробелы и русские буквы.

## 3. Создание базы данных

Откройте `psql` под администратором (`psql -U postgres`) или Query Tool в pgAdmin и выполните:

```sql
CREATE USER taler WITH PASSWORD 'taler' CREATEDB;
CREATE DATABASE talerbank OWNER taler;
CREATE DATABASE talerbank_test OWNER taler;
```

База `talerbank` рабочая, `talerbank_test` нужна только автотестам: они пересоздают в ней схему при каждом запуске, поэтому не храните там ничего нужного.

## 4. Установка зависимостей и настройка

В папке проекта:

```
npm install
npm run setup
```

`npm run setup` создаёт файл `.env` из шаблона `.env.example` и подставляет случайные секретные ключи (подпись сессий и ключ шифрования данных). Существующий `.env` команда не трогает.

Откройте `.env` и при необходимости поправьте:

| Параметр | Значение по умолчанию | Назначение |
|---|---|---|
| `PORT` | 3000 | порт сервера |
| `DATABASE_URL` | `postgres://taler:taler@localhost:5432/talerbank` | подключение к рабочей базе |
| `TEST_DATABASE_URL` | `postgres://taler:taler@localhost:5432/talerbank_test` | база для автотестов |
| `SESSION_SECRET` | случайный | секрет подписи сессий |
| `DATA_KEY` | случайный | ключ AES-256-GCM для паспортных данных и резервных копий (64 шестнадцатеричных символа) |
| `BANK_CODE` | TLRB | код банка в номере IBAN |
| `LOGIN_MAX_ATTEMPTS` | 5 | неудачных входов до блокировки |
| `LOGIN_LOCK_MINUTES` | 15 | длительность блокировки |
| `BACKUP_DIR` | backups | каталог резервных копий |
| `BACKUP_KEEP` | 14 | сколько копий хранить |
| `BACKUP_INTERVAL_HOURS` | 24 | период автокопирования, 0 выключает |
| `PG_BIN_DIR` | пусто | папка `bin` PostgreSQL, если `pg_dump` не найден в `Path` (например `C:\Program Files\PostgreSQL\16\bin`) |

### Почта вместо SMS

В реальном банке коды подтверждения приходят по SMS. В ТалерБанке их можно получать **на электронную почту клиента** (адрес указывается при регистрации), SMS-шлюз не нужен. Для этого задайте параметры SMTP-сервера в `.env`:

| Параметр | Назначение |
|---|---|
| `SMTP_HOST` | адрес почтового сервера; если пусто, почта выключена |
| `SMTP_PORT` | порт: 587 (STARTTLS) или 465 (SSL), по умолчанию 587 |
| `SMTP_SECURE` | `true` для порта 465, иначе `false` |
| `SMTP_USER`, `SMTP_PASS` | логин и пароль (для Gmail и Яндекса нужен **пароль приложения**, а не основной пароль) |
| `MAIL_FROM` | отправитель, например `ТалерБанк <no-reply@talerbank.local>` |

Пример для Gmail: `SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`, `SMTP_SECURE=false`, `SMTP_USER=ваш@gmail.com`, `SMTP_PASS=пароль_приложения`. Для Яндекс Почты: `smtp.yandex.ru`, порт 465, `SMTP_SECURE=true`.

Что даёт включённая почта:

- коды подтверждения (переводы, перевод в другой банк, подписание кредита) приходят письмом, а на странице не показываются;
- уведомления кабинета (платежи, решения по заявкам, напоминания, входы) дублируются на почту; клиент может отключить это в разделе «Безопасность»;
- письма отправляются из очереди (таблица `mail_outbox`): письмо ставится в очередь вместе с операцией, поэтому не уйдёт, если операция откатилась. Неудачные отправки повторяются, после пяти попыток письмо помечается как неотправленное.

Без `SMTP_HOST` всё работает по-старому: код показывается на странице подтверждения («учебная версия»). Для проверки без настоящей почты можно запустить локальный сервер Mailpit (https://mailpit.axllent.org) и указать `SMTP_HOST=localhost`, `SMTP_PORT=1025`: письма будут видны в его веб-интерфейсе на http://localhost:8025.

После изменения `.env` перезапустите сервер. При запуске в консоли будет написано, включена ли почта.

**Важно.** Не теряйте `DATA_KEY`: без него невозможно расшифровать паспортные данные клиентов и восстановить резервные копии. Не публикуйте `.env`: он добавлен в `.gitignore`.

## 5. Создание таблиц и начальных данных

```
npm run db:migrate
npm run db:seed
```

- `db:migrate` применяет SQL-файлы из папки `db/sql` по порядку (23 файла: таблицы, справочники, настройки);
- `db:seed` создаёт служебные счета банка, сотрудников и двух демонстрационных клиентов, пытается получить курсы валют с сайта Национального банка (api.nbrb.by). Если сайт недоступен, используются запасные курсы.

Миграции можно запускать повторно: применяются только новые файлы. После обновления проекта (`git pull`) снова выполните `npm run db:migrate`.

## 6. Запуск

```
npm start
```

В консоли появится строка «ТалерБанк запущен: http://localhost:3000». Откройте этот адрес в браузере.

Для разработки удобнее `npm run dev`: сервер перезапускается при изменении файлов.

Остановить сервер: Ctrl+C в окне, где он запущен.

## 7. Демонстрационные пользователи

Пароль у всех `Taler2026`.

| Логин | Роль |
|---|---|
| `anna`, `igor` | Клиент (со счётом и деньгами) |
| `operator` | Операционист |
| `credit` | Кредитный специалист |
| `monitor` | Специалист по финансовому мониторингу |
| `admin` | Администратор |

Сотрудникам при входе нужна двухфакторная защита. При первом входе система предложит настроить приложение-аутентификатор (Google Authenticator, Яндекс Ключ, Aegis и другие): отсканируйте QR-код, введите шестизначный код и сохраните резервные коды. Для разработки и демонстрации обязательность можно выключить:

```
npm run staff2fa:off
```

Включить обратно: `npm run staff2fa:on`. Это же можно сделать в разделе администратора «Курсы и тарифы», группа «Безопасность».

## 8. Проверка работоспособности

Выполните автотесты:

```
npm test
```

Должно быть написано `169 passed` (число может расти по мере развития проекта). Тесты используют базу `talerbank_test`.

Адрес `http://localhost:3000/health` отвечает `{"status":"ok"}`, если сервер работает.

## 9. Резервное копирование и восстановление

- Копии создаются автоматически по расписанию (`BACKUP_INTERVAL_HOURS`) и вручную в разделе администратора «Резервные копии». Файлы лежат в каталоге `BACKUP_DIR`, шифруются ключом `DATA_KEY`. Хранятся последние `BACKUP_KEEP` копий.
- Для работы нужны `pg_dump` и `pg_restore`. Если они не находятся, задайте `PG_BIN_DIR` в `.env`.
- Восстановление из копии заменяет все текущие данные. Перед ним создайте свежую копию.

## 10. Работа по HTTPS

Для учебной демонстрации достаточно HTTP на localhost. Для настоящего развёртывания поставьте перед приложением обратный прокси (nginx, Caddy, IIS) с сертификатом TLS и передавайте заголовок `X-Forwarded-Proto`. Задайте `NODE_ENV=production` в `.env`: тогда куки сессии помечаются как защищённые (передаются только по HTTPS).

## 11. Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| PowerShell: «выполнение сценариев отключено в этой системе» при `npm` | выполните в PowerShell `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` либо запускайте команды в обычной командной строке `cmd` |
| `ECONNREFUSED` или «password authentication failed» | не запущена служба PostgreSQL, либо в `DATABASE_URL` неверные пользователь, пароль или имя базы |
| `database "talerbank" does not exist` | не выполнен шаг 3, создайте базы |
| `EADDRINUSE` при запуске | порт 3000 занят предыдущей копией сервера. Закройте её окно или выполните `taskkill /F /IM node.exe`, затем `npm start`. Либо смените `PORT` в `.env` |
| После обновления кода страница показывает ошибку «... is not defined» | сервер работает со старой версией: перезапустите его (Ctrl+C и `npm start`) |
| Курсы валют не обновляются | нет доступа к api.nbrb.by. Используются запасные курсы. Администратор может нажать «Обновить курсы с Нацбанка» позже |
| Резервная копия не создаётся | не найден `pg_dump`: задайте `PG_BIN_DIR` |
| Код подтверждения не приходит | если почта не настроена (`SMTP_HOST` пуст), код показан прямо на странице подтверждения. Если настроена: проверьте папку «Спам», адрес в анкете клиента и сообщения в консоли сервера (`Не удалось отправить код на почту`) |
| Сотрудник потерял телефон с аутентификатором | войдите, используя резервный код. Если кодов нет, администратор выполняет `npm run staff2fa:off` на сервере и сотрудник настраивает защиту заново |
| Вход временно заблокирован после неверных паролей | подождите `LOGIN_LOCK_MINUTES` минут. Блокировка снимается сама |

## 12. Структура установленной системы

```
.env                  настройки и ключи (не публиковать)
backups/              зашифрованные резервные копии
db/sql/               схема и начальные данные
db/schema.sql         полный скрипт БД (собирается npm run db:schema)
src/                  код сервера
public/               стили, скрипты, изображения
docs/                 документация
test/                 автотесты
```
