# Сборка docx для записки

Порядок: диаграммы (`npm run uml:classes`, `npm run uml:views`, `npm run er:drawio`) → PNG (`node svg2png.cjs вход.svg выход.png 2`, нужен playwright) → разделы → общий файл.

- `build_13.py шаблон.docx выход.docx` – дополнение к 1.3 (текст в `content_13.py`). Шаблон – docx черновика записки.
- `build_14.py выход.docx` – раздел 1.4 (основа `docs/kursovaya/src/er-part.docx`).
- `build_15.py выход.docx` – раздел 1.5.
- `fig_2.py` – рисунки раздела 2: схема слоёв и три блок-схемы по ГОСТ 19.701-90 (перевод, обслуживание кредитов, вклады). Блок-схемы строит движок раскладки по описанию алгоритма: решение всегда даёт две ветви «Да» влево и «Нет» вправо, ветви закрываются линией слияния, выход в соединитель; колонки соединяются соединителями. PNG через `svg2png.cjs ... 2`.
- `build_2.py выход.docx` – раздел 2 «Проектирование и конструирование ПС» (формулы OMML: в Word отображаются, LibreOffice без пакета Math их не показывает).
- `build_3.py выход.docx` – раздел 3 «Тестирование, проверка работоспособности и анализ полученных результатов» (класс `Doc` из build_2.py с `chap=3`, таблицы `Doc.table`: подпись с выступом 3 см, сетка, шапка повторяется). Рисунки: `fig-test-run.png` (вывод `npm test`, построен из реального запуска), `fig-test-iban.png` и `fig-test-code.png` (сценарии Playwright). Цифры покрытия из `npx vitest run --coverage --coverage.include='server/**'`. В 3.5 жёлтая пометка: дополнить после проверки в Яндекс Браузере, Firefox и Opera.
- `tune_2.py --part 3` – подбор раскладки раздела 3 (`src/layout-3.json`); положение рисунка может быть числом: рисунок после стольких абзацев.
- `split_tables.py вход.docx выход.docx` – «Продолжение таблицы X.X» и повтор шапки. Разбивка считается по PDF из LibreOffice, при правках запускайте заново (скрипт идемпотентен).
- `merge_zapiska.py черновик.docx выход.docx` – общий файл: разделы подставляются в оформление черновика, диаграммы вариантов использования из 1.3 удаляются; рядом пишутся `выход.lo.docx` (копия для LibreOffice) и `выход.pdf`. Рисунки, ушедшие на следующую страницу и оставившие пустоту, автоматически уменьшаются (не более чем на 15 %).
- `check_layout.py файл.pdf|docx [порог_см]` – страницы с пустым местом внизу.
- `tune_layout.py черновик.docx` – подбор порядка блоков 1.5 (результат `docs/kursovaya/src/layout-1.5.json`, читает `build_15.py`).

Нужны `python-docx`, `Pillow`, `soffice` (LibreOffice) и `pdftotext` (poppler).

- `build_4.py выход.docx` – раздел 4 «Руководство по установке и использованию»: 4.1 установка (рисунок `fig-guide-install.png`), 4.2 руководство пользователя по ролям (скриншоты `fig-guide-*.png`, список `GUIDE`).
